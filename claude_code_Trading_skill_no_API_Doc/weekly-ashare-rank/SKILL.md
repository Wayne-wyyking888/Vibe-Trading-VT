# A股短线选股排名（0 API · Claude Code 原生 · T+1 通用）

## 这个 skill 怎么运作

**我（Claude Code）就是大脑，不调用任何外部 LLM API。** 我依次扮演四个 agent，用本机
Python 引擎（免费东财/新浪/腾讯行情）+ 自带 WebSearch 完成"量化+消息+风险+验证"四方辩论。
第四个 agent（验证·复核官）是为了"分析更精准、建议都 verify 过"专设的把关环节。

**核心定位（不局限于周一）**：以**最新有完整数据的交易日 T** 为基准 → 预测 **T+1 买入** →
**持有 ≤N 个交易日**（N 默认 5，用户可指定）。引擎自动判断 T+1 是否跨周末/假期。
- 周五晚上跑 → T=周五, T+1=下周一, 跨周末
- 周三晚上跑 → T=周三, T+1=周四, 不跨周末

## 参数解析（重要）

用户可能这样调用，我要先解析参数（中文冒号/等号/空格都认）：
```
/weekly-ashare-rank 天数=5
/weekly-ashare-rank 天数：3 板块=光通信
/weekly-ashare-rank top=10 hold=5 sector=机器人
```
| 用户写法（任一） | 含义 | 传给引擎 | 默认 |
|---|---|---|---|
| 天数 / 持有 / days / hold / N | 最多持有交易日数 | `--hold-days N` | 5 |
| 板块 / 行业 / sector | 限定板块（模糊匹配） | `--sector X` | 全市场 |
| top / 数量 / 几只 | 最终输出数量 | `--top K` | 8 |

解析不到就用默认值。解析后**复述一遍**给用户确认口径（T、T+1、N、板块、top）。

### 选股模式 = 一句话搞定，我自动编排这几步（用户无需手动跑任何东西）
1. **解析参数** N/板块/top。
2. **权重自校准 + 策略验证（自动，必要时才跑）**：检查 `weights.json` 是否存在、`fwd_days==N` 且 ≤7 天。
   不满足就先自动跑回测刷权重 **再跑一次走样本验证**（共约 1–2 分钟，告诉用户"首次/换持有天数，先校准因子权重并验证排名 edge"）：
   ```powershell
   python "...\ashare_weekly_rank.py" --backtest --hold-days N --bt-sample 60
   python "...\ashare_weekly_rank.py" --validate --hold-days N --bt-sample 60 --val-topk 5 --out "C:\Trading_analysis\data\validate_latest.json"
   ```
   满足就跳过 backtest（权重不天天变，周度重算贴合本 skill 周度定位、避免每日refit追噪声过拟合）；validate 结果若 ≤7 天可直接复用 `validate_latest.json` 的裁定。
3. **跑量化引擎**（引擎会自动读匹配的 weights.json + 自动做跨源价格校验，无需额外参数）：见步骤1命令。
4. **Agent② WebSearch + Agent③ 综合 + Agent④ 验证·复核** → verify 通过后输出最终排名表。
5. 结尾提示：买入日早上想做跳空微调就回一句"复核"，否则按表直接买即可。

### 复核模式（买入日 T+1 早上 9:15–9:25 用，可选）
为什么单独：T 晚上选股时 T+1 价格还不存在，跳空只能买入日早上算。**用户不用跑脚本，说"复核"我来跑**：
```powershell

```
输出每只票跳空%/是否破位 → 可买/等回调/放弃；我据此提醒哪些改等回调、哪些放弃。

> 一句话总结给用户：**平时只需 `/weekly-ashare-rank 天数=5` 一条；backtest+策略验证 我会按需自动跑；每次都会跨源校验价格、给出排名 edge 裁定；recheck 是买入日早上可选的，你说一声我跑。**

- 用 **PowerShell** 跑，**必须** 先刷新 PATH + 加 `dangerouslyDisableSandbox: true`（沙箱拦行情网络）。

### 步骤 1 — Agent ①「量化筛选者」：跑引擎
```powershell
$env:PATH = [System.Environment]::GetEnvironmentVariable("PATH","Machine") + ";" + [System.Environment]::GetEnvironmentVariable("PATH","User")
python "C:\Trading_analysis\Vibe-Trading-VT\claude_code_Trading_skill_no_API_Doc\weekly-ashare-rank\ashare_weekly_rank.py" --hold-days 5 --top 8 --out "C:\Trading_analysis\data\rank_latest.json"

```
引擎输出每只候选：综合分 + 5个分项（动量/量能/技术/盘口/回调）+ 5日%/20日%涨幅 + 量比/当日量 +
尾盘强弱 + 距MA10 + 60日位 + ATR% + 成交额/流通市值 + **信号(N连板/一字/回踩/尾盘强)**。
- 读 stdout 表格 + `rank_latest.json`。注意引擎打印的 **T、T+1、是否跨周末**。
- 引擎已按 `hold-days` 自动调因子权重（超短线重盘口/动量，偏波段重趋势）。

### 步骤 2 — Agent ②「催化剂分析者」：WebSearch 查资讯
对引擎 Top 候选（前 ~10）逐一查最近催化剂，给 **催化剂强度(高/中/低/无)** + 一句话逻辑，
并判断"利好是否已 price-in"（公告前已大涨）。
- **若 T+1 跨周末/假期（引擎会标注）**：额外强制搜两类——
  ① 本周末政策/会议/监管预期（A股政策常周末发）
  ② 候选股 T 日盘后公告（业绩预告/重组/减持/中标/解禁）
- 常规搜索词模板：`"{板块} 政策 利好 最新"`、`"机构强推 A股 本周"`、`"{股票名} 公告 业绩"`、`"A股 下周 风险 解禁"`。
> 纪律：具体数字必须来自 WebSearch 或引擎输出，不得用训练记忆里的旧价/旧数。

### 步骤 3 — Agent ③「风险挑战者」：质疑 + 跳空感知定价 + 排名
逐一挑战并给最终排名：
- **拥挤/过热**：近5日涨幅>12%且量能萎缩、换手>10%、`信号`含 高位连板(≥3) → 降分/剔除。
- **一字板**：`信号`含"一字板"= 次日难买入 → 标注"打板/竞价抢"或放弃，不当常规标的。
- **利好兑现**：催化剂已 price-in → 降分。
- **下行风险**：减持公告/商誉/估值90%分位以上/解禁 → 降分/剔除。
- **综合分** = 量化×0.45 + 催化剂×0.35 + 风险×0.20；置信度：≥80三方一致 / 65–79两方 / 50–64分歧 / <50剔除。
- **跳空感知定价**（关键，因为 T+1 是跳空开盘）：
  - 买入价：回踩型(信号含"回踩")=收盘×0.99 等低吸；突破型=收盘×1.005；**强催化高开预期则注明"竞价高开>3% 就等回调/放弃"**。
  - 止损价：max(收盘 − 1.3×ATR14, 近5日最低×0.99)。
  - 目标价（N 日内）：前高/整数关/斐波那契，且预期收益 ≥ 2×止损幅度（R:R>2:1，否则剔除）。
- **主题集中度**：把 Top 按主题归类，若某主题占比过半 → 提示扎堆风险，建议同主题最多留 1–2 只、单票≤10%仓。

### 步骤 3.5 — Agent ④「验证·复核官」：建议出表前最后一道关（核心：让建议都 verify 过）
> 目的：**不让任何未经核验的数字/逻辑进入最终建议**。本步不通过的项必须降级或剔除，不能硬出。

**A. 策略层 — 排名本身有没有 edge（引用回测，不是拍脑袋）**
读 `validate_latest.json`（步骤2已自动产出/复用）的裁定，**在最终表上方明示一行**：
`策略验证：<verdict>（Top-K超额 +x% · 胜率 y% · 排名IC z · 有效截面 n）`。据此设**置信度上限**：
- `通过` → 置信度可正常给到「高」。
- `弱通过` → 单只置信度最高只能「中高」，并提示"近端 edge 偏弱，建议总仓打折"。
- `未通过/数据不足` → 全部降到「中」及以下，明确告诉用户"本期排名统计显著性不足，建议轻仓或观望"，**绝不报「高」置信**。

**B. 个股层 — 逐只 verify（每只过 5 项，全过才标 ✓，任一不过标 ⚠ 并处置）**
1. **跨源价格**：看引擎 JSON 里每只的 `verify.status`。`存疑(跨源偏差大)` → 该票买入价/止损不可信，先 WebSearch/再拉一次行情人工核对，对不上就**剔除**；`单源未校验`（东财被限流时）→ 标注"仅单源、价格未交叉验证"。
2. **数值自洽**：必须 `止损 < 买入区间下沿 < 目标价`，且 `R:R ≥ 2`（引擎已给 `rr`，<2 的剔除或明确标"盈亏比不足，仅观察"）。
3. **可买性**：`信号` 含「一字板」→ 次日买不进，不当常规标的（仅注明打板客竞价）；高位连板(≥3)→ 强制轻仓。
4. **催化剂可追溯**：最终表里写的每条催化剂，**必须能对应到 Agent② 的某条 WebSearch 结果（带日期/来源）**；凡是只能凭记忆、查不到出处的 → 改写成"未证实"并下调置信度，严禁编造。
5. **数据新鲜度/样本量**：核对引擎输出的 `as_of` 是最新交易日、`spot_source` 与 `sanity_flags`；若有 `⚠universe偏小/种子兜底` → 在风险提示里如实披露"覆盖面有限"。

**C. 产出**：给每只票一个核验标记（`✓已验证` / `⚠存疑:<原因>`），把策略裁定行 + 每只标记带进步骤4的表，并把 validate 裁定回填进结果 JSON 顶层 `validation` 字段（供 HTML 报告显示）。

## 底层命令参考（一般不用手敲，模式判定里我已自动调用）
- 回测刷权重：`... --backtest --bt-sample 60 --hold-days N`（→ weights.json，含权重收缩shrink默认0.5降过拟合；引擎之后自动读取，≤7天复用）
- **策略验证(排名edge)**：`... --validate --hold-days N --bt-sample 60 --val-topk 5 --out validate_latest.json`（→ Top-K超额/胜率/排名IC + 裁定）
- 盘前复核：`python recheck.py --in C:\Trading_analysis\data\rank_latest.json`
- 强制不用回测权重：选股命令加 `--weights none`；强制重拉行情：加 `--refresh`；跳过跨源价格校验：加 `--no-verify`

## 硬性纪律
1. **0 API**：除自带 WebSearch 外不调用任何付费 LLM/数据 API。
2. **真实数据**：行情来自引擎实时拉取，资讯来自 WebSearch，严禁编造/用旧记忆数。
3. **A股特性**：T+1（次日才能卖）、涨跌停、流动性(日均额>1亿)、剔除 ST/次新。
4. **仓位**：单票≤10%，持 3–5 只；明确止损纪律；跨周末提示周末消息面不确定性。
5. **建议必须 verify 过（Agent④）**：① 排名整体 edge 看走样本验证裁定，未通过就不给「高」置信、提示轻仓；
   ② 每只票的价格(跨源)、数值自洽(止损<买入<目标且R:R≥2)、催化剂(可追溯到WebSearch出处)逐项核验，
   不过关就降级或剔除并在「核验」列标 ⚠；③ 置信度上限由验证裁定决定，不得拍脑袋给高分。
6. 全程中文。

## 数据源与容错（引擎内置，无需关心）

- 多镜像轮换 + 指数退避 + 东财熔断 + 当天缓存（防限流）；盘前实时归零时用K线兜底。
